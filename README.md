# Практическая работа 2, вариант 8

CLI-инструмент на Python для графа зависимостей NuGet. Пять этапов
сохранены отдельными рабочими коммитами и тегами `stage-1` ... `stage-5`.
Зависимости получаются самостоятельно средствами стандартной библиотеки:
HTTP NuGet V3, JSON списка версий и XML `.nuspec`. Менеджеры пакетов не
участвуют в получении графа; .NET использован только для сравнения.

## Установка, сборка и запуск

Для анализа нужен Python 3.11+. Для PNG нужны Node.js 22.13+ и Mermaid
CLI 12.0.0. Python-пакеты устанавливать не требуется. Сборка не нужна.
Из корня репозитория установите только рендерер:

```text
npm install
```

Mermaid CLI обычно скачивает свой браузер. На Windows инструмент также
автоматически находит установленный Chrome или Edge. Явный путь можно
задать переменной `MERMAID_BROWSER`. Переменная `MERMAID_CLI` позволяет
указать другой путь к `@mermaid-js/mermaid-cli/src/cli.js`.

```text
run.bat examples\logging.toml
python -B -m src.cli examples/test.toml
examples\demo.bat
python -B -m unittest discover -s tests -v
```

`demo.bat` создает изображения трех настоящих пакетов. Итоговый CLI
печатает пути сохраненных `.mmd` и `.png`. В `output` находятся результаты,
исключенные из Git, чтобы не хранить бинарные файлы и артефакты.

Без установленного рендерера интеграционный тест PNG пропускается;
остальные проверки выполняются. При выполнении работы пройдены все
17 тестов, включая запуск настоящего Mermaid CLI.

## Все параметры TOML

В CLI передается только путь к конфигурации. Шесть обязательных полей:

| Поле | Значение |
| --- | --- |
| `package` | Имя NuGet-пакета; в тестовом режиме большие латинские буквы. |
| `repository` | URL NuGet V3 service index/flat container либо путь к тестовому JSON. |
| `test_mode` | `false` для NuGet, `true` для файла тестового репозитория. |
| `version` | Конкретная версия корня, например `8.0.0`. |
| `output` | Путь будущего PNG. Mermaid записывается рядом с расширением `.mmd`. |
| `filter` | Подстрока исключаемых имен; `""` отключает исключение. |

Дополнительное поле `framework` принимает `net8.0` (по умолчанию) или
`net9.0` и выбирает совместимую группу зависимостей из `.nuspec`.
Все относительные пути отсчитываются от каталога TOML.

```toml
package = "Microsoft.Extensions.Logging"
repository = "https://api.nuget.org/v3/index.json"
test_mode = false
version = "8.0.0"
output = "../output/logging.png"
filter = ""
framework = "net8.0"
```

Отсутствующие/лишние поля, неверные типы, имена, URL, пути и версии
проверяются. Ошибки TOML, сети, JSON/XML и рендерера сообщаются без
traceback; код завершения 1. Успешное выполнение имеет код 0.

## Анализ и все режимы

1. Читается конфигурация. В реальном режиме из service index находится
   `PackageBaseAddress/3.0.0`, затем загружается `.nuspec` заданной версии.
2. Выбирается одна наиболее подходящая группа TFM: современный .NET,
   затем netcoreapp/netstandard, затем группа без TFM.
3. Граф получается рекурсивным BFS: целый уровень обрабатывается перед
   рекурсивным переходом к следующему. Общие вершины запрашиваются раз.
4. Имена NuGet и фильтр сравниваются без учета регистра. Исключение
   происходит до запросов метаданных и обрывает обход через такой пакет.
   Если фильтр исключает сам корень, возвращается ошибка.
5. Каждое ребро самостоятельно разрешается на минимальную подходящую
   версию. Поддерживаются точные версии, минимумы и интервалы NuGet;
   prerelease учитывается при его явном указании в диапазоне.
6. Вершина имеет имя и версию. Циклические ребра и петли сохраняются,
   но не вызывают бесконечного обхода.
7. Создается Mermaid `flowchart LR`. PNG отрисовывается именно из этого
   текста настоящим Mermaid CLI. Корень выделен синим.

Это анализ графа, а не полный решатель NuGet Restore: разные версии
одного имени могут быть отдельными вершинами. Конфликты между диапазонами
не объединяются глобально. Нет анализа RID, старого .NET Framework
и платформенных суффиксов TFM. Выбранные примеры совместимы с `net8.0`.

## Тестовый репозиторий и примеры

Файл JSON представляет карту `имя: [имена прямых зависимостей]`.
Все имена состоят из больших латинских букв, ссылки должны существовать.
Версия каждой вершины в этом режиме равна `version` из TOML.

```json
{"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}
```

| Конфигурация в `examples` | Проверяемый случай |
| --- | --- |
| `test.toml` | Ветвление и общая зависимость. |
| `filter.toml` | Исключение D. |
| `cycle.toml` | Цикл A → B → C → A. |
| `self.toml` | Петля A → A. |
| `isolated.toml` | Пакет без зависимостей. |
| `newtonsoft.toml` | Newtonsoft.Json 13.0.3, 1 вершина. |
| `configuration.toml` | Configuration 8.0.0, 3 вершины и 3 ребра. |
| `logging.toml` | Logging 8.0.0, 6 вершин и 7 ребер. |

## Проверка отдельных этапов

Откройте соответствующий тег, например `git switch --detach stage-4`.
После проверки вернитесь командой `git switch main`.

| Тег | Поведение CLI этого коммита |
| --- | --- |
| `stage-1` | Проверка TOML и вывод всех параметров `ключ=значение`. |
| `stage-2` | Вывод всех прямых зависимостей указанной версии. |
| `stage-3` | Полный граф, порядок BFS и диагностика циклов. |
| `stage-4` | Режим `--load-order`, зависимости перед потребителями. |
| `stage-5` | Сохранение Mermaid и PNG. |

На этапе 4 команда `python -B -m src.cli examples/test.toml --load-order`
включает порядок загрузки. Корень стоит последним, независимые вершины
упорядочены по имени; для циклов строгий порядок невозможен.
Вывод параметров, прямых зависимостей и порядка загрузки относится
только к соответствующим этапам, как требует задание.

## Функции и устройство кода

Все функции и классы имеют docstring с назначением. Основные интерфейсы:

- `config.load_settings`: TOML; `validate_values`, `require_text`,
  `validate_repository`, `validate_output`: проверки полей и путей.
- `repository.fetch_bytes`, `fetch_json`: HTTP; `make_repository`: выбор
  источника; `validate_test_graph`: проверка файлового графа.
- `NugetRepository.direct`, `resolve`: XML зависимости и выбор версии;
  `TestRepository.direct`, `resolve`: зависимости тестовых вершин.
- `manifest.local_name`, `framework_score`, `select_group`,
  `parse_manifest`, `read_dependencies`: XML и выбор совместимой группы.
- `versions.version_key`, `normalize_version`: версии;
  `range_bounds`, `satisfies`, `meets_lower`, `meets_upper`,
  `resolve_version`: проверка диапазонов и минимальная версия.
- `GraphBuilder.build`, `visit_level`: рекурсивный BFS;
  `excluded`, `intern`: фильтр и уникальные вершины;
  `cycle_paths`, `print_graph`: диагностика этапа 3.
- `ordering.reverse_edges`, `load_order`, `print_load_order`:
  топологический порядок этапа 4 и его вывод.
- `visualization.package_label`, `to_mermaid`: подписи и текст;
  `renderer_command`, `browser_path`: поиск средств отрисовки;
  `render_png`, `png_size`, `save_visualization`: рендеринг и запись.
- `cli.main`: последовательность операций и обработка ошибок.
