# Практическая работа 2, вариант 8

Инструмент анализа и визуализации зависимостей NuGet на Python.
Этапы 1-4: CLI, TOML-конфигурация и полный граф зависимостей конкретной
версии пакета. Вывод параметров был доступен только на этапе 1, список
прямых зависимостей — только на этапе 2.

## Запуск и сборка

Python 3.11 или новее. Сборка и дополнительные пакеты пока не нужны.
Из корня репозитория выполните:

```text
run.bat examples\test.toml
run.bat examples\logging.toml
python -B -m src.cli examples/test.toml
python -B -m unittest discover -s tests -v
```

## Настройки TOML

| Поле | Назначение |
| --- | --- |
| `package` | Имя пакета; в тестовом режиме только большие латинские буквы. |
| `repository` | URL NuGet V3 или путь к JSON-файлу тестового репозитория. |
| `test_mode` | `true` для файла, `false` для настоящего NuGet. |
| `version` | Конкретная версия пакета, например `8.0.0`. |
| `output` | Имя PNG-файла, относительный путь от TOML. |
| `filter` | Подстрока исключаемых имен; пустая строка отключает фильтр. |
| `framework` | Дополнительно: `net8.0` по умолчанию или `net9.0`. |

Отсутствующие и неизвестные поля, неверные типы, пути, URL и версии
вызывают понятное сообщение и код завершения 1. Все пути в файле
разрешаются от его каталога. Исходные файлы находятся в `src`, проверки
в `tests`, примеры в `examples`.

## Получение зависимостей

Программа сама читает NuGet V3 service index, находит PackageBaseAddress
и получает XML `.nuspec` конкретной версии. Используется одна группа
зависимостей для заданного `framework`: подходящий современный .NET,
затем netcoreapp/netstandard, затем группа без TFM. Менеджеры пакетов
и сторонние библиотеки для получения зависимостей не используются.
На этапе 2 выводятся все прямые зависимости с диапазонами из манифеста.
JSON тестового репозитория содержит карту `имя: [имена зависимостей]`.

## Граф и тестовый режим

Граф строится рекурсивным BFS: сначала обрабатывается целый уровень,
затем функция рекурсивно переходит к следующему. Имена NuGet сравниваются
без учета регистра. Вершина включает имя и конкретную версию. Для
каждого диапазона самостоятельно выбирается минимальная подходящая
версия из NuGet V3. Полное разрешение конфликтов NuGet Restore пока не
воспроизводится.

Непустой `filter` исключает совпадающие имена без учета регистра еще до
запроса метаданных, вместе с дальнейшим обходом через них. Исключение
корня считается ошибкой. Посещенные вершины не запрашиваются повторно;
циклы и петли сохраняются в графе и диагностируются.

Примеры: `examples/test.toml` (общая зависимость), `cycle.toml` (цикл),
`self.toml` (петля), `isolated.toml` (одиночная вершина), `filter.toml`
(исключение D). Запуск: `python -B -m src.cli examples/cycle.toml`.

## Порядок загрузки (этап 4)

`python -B -m src.cli examples/test.toml --load-order` выводит зависимости
перед потребителями и сам корень последним. Среди независимых вершин
используется порядок имен. Для циклов и петель сообщается, что строгий
порядок не существует. Результаты сопоставлены с реальным NuGet Restore
в .NET SDK: подробности и объяснение отличий в
`docs/stage4-comparison.md`. Этот режим относится только к этапу 4.
